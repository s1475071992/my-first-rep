# GCClassic Build-Once / Run-Many Design

## Goal

Compile the pinned GCClassic 14.7.1 reference producer once, freeze that build as an immutable GitHub Actions artifact, and reuse the exact same executable/source identity for all later diagnostic configuration, seasonal, and regional reference cases.

## Scientific constraints

- GCClassic wrapper remains pinned to tag `14.7.1` and SHA `c36ecd760c6663a62769f05a7449c927b8faf54b`.
- GEOS-Chem science source remains pinned to SHA `b9f570e2c7a98b308004cd07e2985a12a47b6f5c`.
- Runtime configuration changes may touch `geoschem_config.yml`, `HEMCO_Config.rc`, `HISTORY.rc`, time windows, seasons, and holdout regions.
- Runtime configuration changes must not rebuild GCClassic and must not modify TPCORE or other transport numerical source.
- The frozen seasonal matrix and holdout-region matrix remain unchanged.
- The existing HEMCO missing-restart-species policy (`SPC_ ... CYS`) and transport-audit HISTORY collection policy remain runtime configuration concerns, not build concerns.

## Architecture

Two workflows have separate responsibilities.

### 1. `gc14-frozen-build`

`.github/workflows/gc14-build.yml` is the only workflow allowed to bootstrap and compile GCClassic. It runs when its build recipe or pinned bootstrap inputs change, or by manual dispatch.

It creates a frozen bundle containing:

- the exact GCClassic 14.7.1 source checkout and submodules;
- the compiled/installed 4x5 MERRA2 72L TransportTracers run-directory template;
- source/toolchain provenance generated by `bootstrap_gcclassic.sh`;
- the installed `gcclassic` executable and its SHA256;
- a build manifest with the GitHub build run id and immutable source identities.

The run-directory `build/`, runtime `ExtData`, runtime restarts, and runtime diagnostic output are excluded. They are not part of the frozen executable identity.

The bundle is uploaded as `gc14-7-1-frozen-build-<BUILD_RUN_ID>`.

### 2. `gc14-reference-producer`

`.github/workflows/gc14-reference-producer.yml` never bootstraps, configures CMake, compiles, or installs GCClassic.

Instead it:

1. reads `config/frozen_gcclassic_build.json`;
2. downloads the exact artifact from the pinned build run id;
3. verifies the bundle SHA256 before extraction;
4. extracts the frozen source/provenance/run-directory template into the same deterministic `/tmp/gc14-reference` layout;
5. applies only runtime case configuration (`geoschem_config.yml`, `HEMCO_Config.rc`, `HISTORY.rc`);
6. performs dry-run/input download/runtime/validation/package steps;
7. records both the build run id and frozen executable SHA256 in reference evidence.

## Pinning contract

`config/frozen_gcclassic_build.json` is the single explicit pointer from run-many to build-once. It contains:

- `build_run_id`;
- `artifact_name`;
- `bundle_filename`;
- `bundle_sha256`;
- `gcclassic_version`;
- `gcclassic_sha`;
- `geoschem_sha`;
- `executable_sha256`.

A new build artifact does not change reference runs automatically. Switching the reference producer to a different binary requires an explicit commit updating this pin file after the new build has succeeded and its bundle digest has been verified.

## Artifact layout

The uploaded GitHub artifact contains:

```text
frozen-build/
  gc14-7-1-frozen-build.tar.gz
  gc14-7-1-frozen-build.tar.gz.sha256
  frozen_build_manifest.json
```

The tarball expands under `/tmp/gc14-reference` to:

```text
GCClassic/
provenance/
rundirs/gc_4x5_merra2_TransportTracers/
```

The run-directory template contains the installed executable but not its CMake build directory.

## Trigger policy

Build workflow push triggers are restricted to build identity/recipe files:

- `.github/workflows/gc14-build.yml`
- `scripts/bootstrap_gcclassic.sh`
- `scripts/create_transporttracers_rundir.sh`
- `scripts/package_frozen_gcclassic_build.sh`

Reference workflow changes, HEMCO/HISTORY patches, seasonal matrix changes, and validation-script changes do not trigger a rebuild.

## Acceptance criteria

1. The frozen-build workflow succeeds and uploads exactly one build artifact.
2. The pin file matches the downloaded bundle SHA256 and executable SHA256.
3. The reference workflow contains no `cmake`, `make`, `bootstrap_gcclassic.sh`, or run-directory creation step.
4. The reference workflow downloads the explicitly pinned build run and verifies the bundle SHA256 before extraction.
5. The same frozen executable runs the existing JJA 2019-07-01 1-hour case successfully.
6. PassiveTracer endpoint validation and evidence packaging still pass.
7. Reference provenance records the frozen build run id and executable SHA256.
